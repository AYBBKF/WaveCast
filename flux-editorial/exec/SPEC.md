## 4. Surfer : boucle de score
1. Éditeur existant indiqué dans la fiche → l'utiliser. Sinon `content_editor__create` (workspace_id 1403832, main_keyword, location "Morocco", device "mobile", idempotency_key = slug). L'appel peut expirer à 60 s : retrouve alors l'éditeur avec `content_editor__list` (sort inserted_at desc) et attends `state: completed` en relançant `content_editor__get` toutes les ~30 s (utilise Bash `sleep` interdit au premier plan : fais d'autres étapes, ex. image, entre deux contrôles).
2. `seo_guidelines__get` (terms_scope "included") : lis les termes, la structure, les PAA. Ne recopie pas les concurrents.
3. Rédige, puis `content__update` (format html, le corps SANS le wrapper freeform). Attends quelques secondes puis `content_score__get` jusqu'à ce que `total.status` ne soit plus `calculating`.
4. Le score retenu est **`total.score`** (Content Score global). Il doit être **entre 80 et 90 inclus**. En dessous : `seo_guidelines__get_terms_coverage`, ajoute les termes manquants naturellement (sans bourrage), réessaie. Au-dessus de 90 : retire du bourrage. Maximum 6 itérations ; ne sacrifie jamais la lisibilité ni la véracité.
5. Consigne le score réellement obtenu (et seo/ai_search si renvoyés).

No readable text, no logos, no brands, no watermark. » Cohérent avec les visuels actuels du site : photos réalistes de scènes de travail au Maroc.
- Télécharge (curl), puis `convert in.webp -strip -resize 1200x -quality 75 img/<slug>.webp`. **Regarde l'image (outil Read sur une copie jpg réduite)** : si elle contient du texte illisible marqué, des mains déformées ou ne correspond pas au sujet, régénère une fois.
- Texte alternatif fidèle à ce que montre réellement l'image (pas de mots-clés plaqués), 80 à 150 caractères.
- Optimisation : `python3 -c "from PIL import Image; im=Image.open('img/<slug>-src.webp').convert('RGB'); w=960; im.resize((w,round(im.height*w/im.width)),Image.LANCZOS).save('img/<slug>.webp','WEBP',quality=55,method=6)"`.
- **NE TÉLÉVERSE PAS l'image** (le téléversement par URL échoue et le base64 est trop lourd à recopier ; c'est traité séparément). Consigne simplement le chemin du fichier optimisé et l'alt dans le JSON (champ "image_locale"), media_id null.

## 6. WordPress
- Nouvel article : `wp_add_post` avec title (= H1), content, slug (fiche), excerpt (= meta description, 140 à 155 caractères, avec la requête principale), categories (ids : 1 Automatisation des processus ; 55 Agents IA ; 56 Chatbots & expérience client ; 57 CRM, ventes & marketing IA ; 30 Immobilier), tags (cherche le tag avec wp_list_tags search, sinon wp_add_tag ; 2 à 4 tags), comment_status "closed".
  - Si score vérifié entre 80 et 90 : status "future" et **date_gmt "<date de la fiche>T08:00:00"** (n'envoie PAS `date`). Raison : WordPress calcule Africa/Casablanca à UTC+0 alors que le Maroc est à UTC+1 ; 08:00 GMT = 09:00 heure marocaine réelle (WordPress affichera 08:00). Sinon status "draft".
- Nouvelle page : `wp_add_page` mêmes règles, avec `parent` si indiqué.
- Enrichissement d'un contenu publié : sauvegarde d'abord le contenu actuel (`wp_get_post` context edit) dans backup/<id>.json ; garde le slug ; mets à jour titre/contenu/extrait via `wp_update_post` (content = {"raw": "..."}, title = {"raw": "..."}, excerpt = {"raw": "..."}) **uniquement si score 80–90 vérifié** (mise en ligne immédiate : WordPress ne programme pas les mises à jour). Sinon n'écris rien dans WordPress et enregistre le HTML dans html/.
